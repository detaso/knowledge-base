Visual media makes complex procedures easier to follow and helps readers orient themselves in a UI or workflow. The knowledge base editor lets you embed images, videos, and downloadable file attachments directly inside articles — no third-party hosting required. All uploaded media is served from your workspace's built-in storage and delivered over a global CDN.

<Warning>
  All uploaded media counts toward your workspace storage quota. Monitor your usage from **Settings → Storage**. Upgrading your plan increases your storage limit. Deleting images or file attachments from articles frees up quota, though assets are held in a recovery queue for 30 days before permanent removal.
</Warning>

## Images

Images can be inserted into any article using three methods:

<Steps>
  <Step title="Drag and drop">
    Drag an image file from your desktop or file browser directly onto the editor canvas. Drop it at the position where you want it to appear. The editor uploads the file automatically and inserts it inline.
  </Step>
  <Step title="Paste from clipboard">
    Copy an image to your clipboard (for example, with a screenshot tool) and press **Cmd+V** (macOS) or **Ctrl+V** (Windows/Linux) while the editor is focused. The image uploads immediately.
  </Step>
  <Step title="Use the slash command">
    Type `/image` in the editor to open the image upload dialog. You can upload a file from your device or paste a public image URL to embed a remotely hosted image.
  </Step>
</Steps>

**Supported formats:** PNG, JPEG, GIF, WebP

**Maximum file size:** 10 MB per image

After inserting an image, click it to reveal the image toolbar. From there you can:

- Edit the **alt text** — describe what the image shows for accessibility and SEO
- Adjust **alignment** (see [Image Alignment](#image-alignment) below)
- Set a **caption** that appears below the image
- **Replace** the image without losing your alt text and caption

<Note>
  Deleted images are moved to a recovery queue and permanently removed from storage after 30 days. During that window, you can restore a deleted image from **Settings → Storage → Deleted Media**.
</Note>

## Videos

Embed videos from external platforms or upload video files directly.

<Tabs>
  <Tab title="YouTube and Vimeo">
    Paste a YouTube or Vimeo URL on a blank line in the editor and press **Enter**. The editor automatically detects the URL and converts it into a responsive embedded video player. The video plays inline without sending readers to an external site.

    Supported URL formats include standard watch URLs, shortened URLs (`youtu.be/…`), and Vimeo privacy-hashed URLs.
  </Tab>
  <Tab title="Direct Upload (MP4)">
    Type `/video` to open the video upload dialog, then select an MP4 file from your device. Uploaded videos are transcoded for web playback and streamed from your workspace CDN.

    **Supported format:** MP4 (H.264 recommended)

    **Maximum file size:** 500 MB per video

    Upload time varies with file size and your connection speed. The editor shows an upload progress bar — you can continue writing in other parts of the article while the video uploads in the background.
  </Tab>
</Tabs>

## File Attachments

Attach PDFs, spreadsheets, design files, or any other document for readers to download directly from the article.

To attach a file:

1. Type `/file` in the editor to open the file attachment dialog.
2. Select the file from your device.
3. The file appears as a styled download link inside the article, showing the file name, type icon, and size.

Readers click the attachment block to download the file. Attachments are stored in your workspace storage and count toward your storage quota.

<Tip>
  Use file attachments for supplementary resources — detailed specifications, templates, or data exports — that are too large or complex to embed as readable content. Keep the core explanation in the article body so readers don't have to download a file just to follow the main instructions.
</Tip>

## Image Alignment

Control how images sit within your article layout using the alignment options in the image toolbar.

<CardGroup cols={3}>
  <Card title="Left" icon="align-left">
    Floats the image to the left with text wrapping around the right side. Best for smaller images or icons used alongside explanatory text.
  </Card>
  <Card title="Center" icon="align-center">
    Centers the image as a standalone block with no text wrap. Use this for screenshots and diagrams that should stand on their own.
  </Card>
  <Card title="Right" icon="align-right">
    Floats the image to the right with text wrapping around the left side. Mirrors the left-float layout for right-aligned supplementary visuals.
  </Card>
</CardGroup>

Switching an image between **inline** and **block** mode changes whether surrounding text wraps around it (inline) or the image occupies its own full-width row (block). Use block mode for most screenshots and diagrams to keep the layout clean.

## Best Practices

Follow these guidelines to keep your media accessible, performant, and professional.

<Accordion title="Use descriptive alt text for every image">
  Alt text is read aloud by screen readers and displayed when an image fails to load. Describe what the image shows — not what it is. Instead of "screenshot", write "The Settings panel open to the Billing tab, showing the current plan and a Cancel Subscription button." Aim for one to two concise sentences.
</Accordion>

<Accordion title="Compress images before uploading">
  Large images slow down article load times. Run screenshots and photos through a compression tool (such as Squoosh, ImageOptim, or TinyPNG) before uploading. For most UI screenshots, PNG compression can reduce file size by 50–70% with no visible quality loss.
</Accordion>

<Accordion title="Capture screenshots at 2× resolution for retina displays">
  Take screenshots at 2× (or "Retina") resolution so they appear crisp on high-DPI monitors. In macOS, the default screenshot tool captures at 2× on Retina screens automatically. On Windows, use a tool that supports scaling, or set your display scaling to 200% before capturing.
</Accordion>

<Accordion title="Prefer static images over animated GIFs for tutorials">
  Animated GIFs are large in file size and loop indefinitely, which can distract readers. For showing multi-step interactions, consider an embedded video (which can be paused) or a numbered series of static screenshots instead.
</Accordion>
