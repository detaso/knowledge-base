The REST API gives you full programmatic access to your knowledge base content. Use it to build custom integrations, sync articles with external systems, automate content publishing pipelines, or pull knowledge base data into your own products. Every operation available in the dashboard — creating articles, managing categories, searching content — is available through the API.

## Authentication

All API requests must include a valid API key. To generate one, go to **Settings > API > Generate API Key** in your dashboard. Copy the key immediately — for security reasons, it is only shown once.

Pass your API key in the `Authorization` header of every request:

```bash
curl https://api.kb.app/v1/articles \
  -H "Authorization: Bearer your_api_key_here"
```

Requests made without a valid API key return a `401 Unauthorized` response.

<Note>
  API keys inherit the same permissions as the user who created them. For content creation and editing operations, generate your key while logged in as a user with the **Editor** role or above. A Viewer-role API key can only read published, publicly visible content.
</Note>

## Base URL

All API endpoints are available under the following base URL:

```text
https://api.kb.app/v1
```

## Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/articles` | List all published articles. Supports query params: `?category=`, `?tag=`, `?page=`, `?limit=` |
| `GET` | `/articles/:id` | Get a single article by its ID |
| `POST` | `/articles` | Create a new article |
| `PUT` | `/articles/:id` | Update an existing article |
| `DELETE` | `/articles/:id` | Permanently delete an article |
| `GET` | `/categories` | List all categories |
| `POST` | `/categories` | Create a new category |
| `GET` | `/search?q=` | Run a full-text search across all accessible articles |
| `GET` | `/collections` | List all collections in your knowledge base |
| `POST` | `/users/invite` | Invite a new user to your knowledge base workspace |

## Rate Limits

To ensure reliable performance for all users, the API enforces rate limits based on your plan:

| Plan | Requests per hour |
|------|-------------------|
| Free | 1,000 |
| Pro | 10,000 |
| Enterprise | Unlimited |

If you exceed your rate limit, the API returns a `429 Too Many Requests` response. The response includes a `Retry-After` header indicating how many seconds to wait before retrying.

## Examples

The sections below show a complete request and response for every endpoint. Replace `your_api_key_here` with your actual API key and substitute the example IDs with real values from your knowledge base.

### GET /articles

List published articles. Use the optional `?category=`, `?tag=`, `?page=`, and `?limit=` query parameters to filter or paginate results.

```bash
curl https://api.kb.app/v1/articles?page=1&limit=20 \
  -H "Authorization: Bearer your_api_key_here"
```

```json
{
  "data": [
    {
      "id": "art_abc123",
      "title": "Getting Started Guide",
      "slug": "getting-started-guide",
      "categoryId": "cat_xyz789",
      "tags": ["onboarding"],
      "status": "published",
      "url": "https://help.yourcompany.com/articles/getting-started-guide",
      "updatedAt": "2024-03-15T10:30:00Z"
    }
  ],
  "page": 1,
  "limit": 20,
  "total": 1
}
```

### GET /articles/:id

Retrieve a single article by its ID.

```bash
curl https://api.kb.app/v1/articles/art_abc123 \
  -H "Authorization: Bearer your_api_key_here"
```

```json
{
  "id": "art_abc123",
  "title": "Getting Started Guide",
  "slug": "getting-started-guide",
  "body": "## Welcome\nThis guide walks you through your first steps...",
  "categoryId": "cat_xyz789",
  "tags": ["onboarding"],
  "status": "published",
  "visibility": "public",
  "url": "https://help.yourcompany.com/articles/getting-started-guide",
  "createdAt": "2024-03-01T09:00:00Z",
  "updatedAt": "2024-03-15T10:30:00Z"
}
```

### POST /articles

Create a new article and assign it to an existing category. Set `"status"` to `"draft"` to save without publishing.

```bash
curl -X POST https://api.kb.app/v1/articles \
  -H "Authorization: Bearer your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "How to Reset Your Password",
    "body": "## Steps\n1. Click Forgot Password on the login screen...",
    "categoryId": "cat_xyz789",
    "tags": ["account", "security"],
    "status": "published",
    "visibility": "public"
  }'
```

A `201 Created` response returns the full article object, including the system-assigned `id`, `slug`, and `url`:

```json
{
  "id": "art_def456",
  "title": "How to Reset Your Password",
  "slug": "how-to-reset-your-password",
  "categoryId": "cat_xyz789",
  "tags": ["account", "security"],
  "status": "published",
  "visibility": "public",
  "url": "https://help.yourcompany.com/articles/how-to-reset-your-password",
  "createdAt": "2024-04-01T12:00:00Z",
  "updatedAt": "2024-04-01T12:00:00Z"
}
```

### PUT /articles/:id

Update the fields of an existing article. Only include the fields you want to change — all other fields remain unchanged.

```bash
curl -X PUT https://api.kb.app/v1/articles/art_def456 \
  -H "Authorization: Bearer your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "How to Reset Your Password (Updated)",
    "tags": ["account", "security", "login"]
  }'
```

```json
{
  "id": "art_def456",
  "title": "How to Reset Your Password (Updated)",
  "slug": "how-to-reset-your-password",
  "categoryId": "cat_xyz789",
  "tags": ["account", "security", "login"],
  "status": "published",
  "visibility": "public",
  "updatedAt": "2024-04-02T08:15:00Z"
}
```

### DELETE /articles/:id

Permanently delete an article. This action cannot be undone.

```bash
curl -X DELETE https://api.kb.app/v1/articles/art_def456 \
  -H "Authorization: Bearer your_api_key_here"
```

A successful deletion returns `204 No Content` with an empty body.

### POST /categories

Create a new category. Set `"parentId"` to another category's ID to create a subcategory.

```bash
curl -X POST https://api.kb.app/v1/categories \
  -H "Authorization: Bearer your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Integrations",
    "parentId": null
  }'
```

```json
{
  "id": "cat_rst345",
  "name": "Integrations",
  "slug": "integrations",
  "parentId": null,
  "articleCount": 0,
  "createdAt": "2024-04-03T10:00:00Z"
}
```

### GET /search?q=

Run a full-text search across all accessible articles. Pass your query in the `q` parameter.

```bash
curl "https://api.kb.app/v1/search?q=reset+password" \
  -H "Authorization: Bearer your_api_key_here"
```

```json
{
  "query": "reset password",
  "data": [
    {
      "id": "art_def456",
      "title": "How to Reset Your Password (Updated)",
      "excerpt": "Click Forgot Password on the login screen to receive a reset link...",
      "url": "https://help.yourcompany.com/articles/how-to-reset-your-password",
      "categoryId": "cat_xyz789"
    }
  ],
  "total": 1
}
```

### GET /collections

List all collections in your knowledge base. Collections group related articles across multiple categories.

```bash
curl https://api.kb.app/v1/collections \
  -H "Authorization: Bearer your_api_key_here"
```

```json
{
  "data": [
    {
      "id": "col_ghi678",
      "name": "New User Onboarding",
      "slug": "new-user-onboarding",
      "articleCount": 6,
      "updatedAt": "2024-03-20T14:00:00Z"
    }
  ],
  "total": 1
}
```

### POST /users/invite

Invite a new member to your knowledge base workspace by email address. The invited user receives an email with a link to accept the invitation and set their password.

```bash
curl -X POST https://api.kb.app/v1/users/invite \
  -H "Authorization: Bearer your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "newmember@yourcompany.com",
    "role": "editor"
  }'
```

```json
{
  "id": "inv_jkl901",
  "email": "newmember@yourcompany.com",
  "role": "editor",
  "status": "pending",
  "invitedAt": "2024-04-04T09:30:00Z",
  "expiresAt": "2024-04-07T09:30:00Z"
}
```

<Note>
  Only users with the **Admin** role or above can invite new members via the API. The `role` field accepts `viewer`, `editor`, or `admin`.
</Note>
