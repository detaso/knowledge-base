## Webhooks

Webhooks let you receive real-time HTTP POST notifications whenever something changes in your knowledge base. To set one up, go to **Settings > Integrations > Webhooks** and enter the URL of the endpoint you want to receive events. Your server must respond with a `2xx` status code within 10 seconds to acknowledge receipt.

The following events are currently supported:

- `article.published` — fired when an article is first published
- `article.updated` — fired when a published article is edited and saved
- `article.deleted` — fired when an article is permanently deleted
- `category.created` — fired when a new category is created

Each webhook delivery includes a JSON payload with the event name, a UTC timestamp, and a `data` object describing the affected resource. Here is a sample payload for an `article.published` event:

```json
{
  "event": "article.published",
  "timestamp": "2024-03-15T10:30:00Z",
  "data": {
    "id": "art_abc123",
    "title": "Getting Started Guide",
    "url": "https://help.yourcompany.com/articles/getting-started",
    "category": "onboarding",
    "author": "jane@yourcompany.com"
  }
}
```

You can use webhook payloads to trigger cache invalidations, sync content to external systems, notify stakeholders, or build custom automations without polling the API.

<Note>
  Zapier and webhook integrations are available on the **Pro plan and above**. Upgrade your workspace in **Settings > Billing** to unlock these features.
</Note>
